# 360-Degree Audit — 2026-08-29

Second audit of this repository, run at v0.4.0. Four releases were cut between
this report and the one before it, and none of them carried an audit — the gap
this pass closes, and the reason a check now fails a release whose newest audit
predates the previous one.

pyomb is a headless library, so this follows `360-headless` as the first report
did: the Value and Discovery perspectives do not apply, and the Quality
perspective is re-projected into nine engineering dimensions, each reviewed
under its own restated lens.

Every finding below carries the command or file that demonstrates it. Nothing
here is marked UNVERIFIED. One candidate finding was dropped and one was
rewritten rather than reported as filed; both are recorded under the dimension
they belong to.

The 2026-08-18 report is left exactly as written. Its C- is an observation of
that date, not a value to re-derive, and the distance between the two grades is
the record of what the four releases changed.

## Current bottleneck

No single dimension is the bottleneck any more, which is itself the finding.
Three sit at B+ for unrelated reasons: the codec does not range-check the
fields a specification bounds, cognitive complexity is still ungated, and the
release procedure's ordering rule is enforced by nothing.

The previous bottleneck is gone. Secret scanning, push protection and
Dependabot are enabled, CodeQL and bandit both run, every action is pinned to a
commit SHA, and `main` is protected with the administrator exemption off. Those
were three critical findings in August and are now none.

What replaces a bottleneck is a spread. Each remaining item is bounded, tracked
and cheap on its own, and no one of them blocks a release.

## Architecture — Grade: A

| # | Sub-dimension | Status | Finding | Reproduction |
| --- | --- | --- | --- | --- |
| 1 | Layering | PASS | The codec imports no I/O | Searching `packets.py`, `errors.py` and `defines.py` for socket, ssl, select or threading imports returns nothing |
| 2 | Dependency direction | PASS | Nothing imports the simulators | Searching `src/` for the simulator module names hits only their own files and the deferred binding in `__init__.py` |
| 3 | Cycles | PASS | The import graph is acyclic | `defines`, `errors` and `logger` are leaves; `packets` reads `errors`; `stream` reads both; the simulators read everything |
| 4 | Layout | PASS | The `src/` layout is real, not cosmetic | The suite imports the installed package, and `pyomb.__file__` resolves under `src/`; `grep -rn "sys.path" tests/` prints nothing |

The four properties the first audit found hold unchanged, and the simulators
are now reached through a module `__getattr__` rather than an eager re-export,
so `import pyomb` costs nothing for a caller that never touches them. That is
the one structural change since August, and it strengthens sub-dimension 2
rather than weakening it: the names are still exported, and the modules behind
them are not run until asked for.

This remains the strongest dimension, and the reason the rest is tractable.

## API contract — Grade: A-

| # | Sub-dimension | Status | Finding | Reproduction |
| --- | --- | --- | --- | --- |
| 1 | Explicit surface | PASS | `__all__` lists 31 names and every one resolves | Importing the package and testing each name against it reports no unresolved entries; a search for star imports under `src/` returns nothing |
| 2 | Typing | PASS | mypy strict passes with a per-module freeze | `python -m mypy` reports no issues across 8 source files |
| 3 | Naming | PARTIAL | Seven public methods on the simulators are camelCase | Reading each class's own namespace rather than its inherited one gives `sendRequest` and `waitResponse` on the client, and `getPeers`, `setConnLimit`, `setDataHandler`, `setDelay` and `setFail` on the server. Tracked as #192 |

The surface grew from 28 names to 31 and the export list is now asserted rather
than trusted — `__all__` is a list of strings, so an entry can name nothing,
and a test resolves every one against the live package.

Sub-dimension 3 is narrower than it looks from a plain `dir()`, which is worth
recording because the naive reading inflates it. `Logger` appears to carry
thirteen camelCase methods and owns none of them: they are `logging.Logger`'s,
and renaming them is not this project's decision. The same is true of
`getName`, `setName`, `isDaemon` and `setDaemon` on the server, which belong to
`threading.Thread`. Seven names are the project's own, and those seven are the
ones #192 can move.

## Protocol correctness — Grade: B+

| # | Sub-dimension | Status | Finding | Reproduction |
| --- | --- | --- | --- | --- |
| 1 | Wire assertions | PASS | 118 bytes constants across 32 of 65 test files | Parsing each test module and counting `ast.Constant` nodes whose value is `bytes` |
| 2 | Checksum vectors | PASS | CRC values come from outside the library | `tests/test_rtu_crc.py` cites crccalc.com and the reference implementation in the Modbus over Serial Line specification |
| 3 | Type hierarchy | PASS | The Liskov freeze is gone | The mypy overrides in `pyproject.toml` name only `no-untyped-call` and `no-untyped-def`; searching the file for `"override"` returns nothing |
| 4 | Field ranges | FAIL | The serializer builds a frame the specification forbids | A Read Holding Registers PDU with a quantity of `0x07D1`, one past the specification's `0x07D0` cap, serializes without complaint to `0001000000060103000007d1`. Tracked as #196 |

Sub-dimension 1 is counted differently from the first report and the two
numbers are not comparable. That report scanned for byte-string escapes and
reported 510; the same pattern run today returns 15812, because it also matches
every `\x` inside an ordinary string. Parsing each module and counting bytes
constants gives 118, which is a count of vectors rather than of characters
inside them. The AST number is the one to carry forward — it cannot drift with
how a vector is written, and it is what a later audit should re-run.

Sub-dimension 3 closed between the two audits. The first report found 123
Liskov violations frozen by error code; the freeze no longer carries `override`
at all, so the declared and actual signatures now agree.

Sub-dimension 4 is the one open gap, and its framing needs care. This library
is a codec *and* a pair of simulators for exercising other implementations, so
emitting a frame a device will reject is sometimes the point. The finding is
not that the serializer must refuse it — it is that a caller has no way to ask
for the check, and the specification's limits are written down nowhere in the
tree. #196 carries the work; its opening clause is stale and is corrected
below.

This is the dimension that moved most. Coverage went from 84% to 96%, and

sub-dimension 3 is a PASS reporting the lowest number rather than a finding.

One candidate finding was dropped here. The suite's two remaining
`DeprecationWarning`s looked like a finding until read: one is `ssl.OP_NO_TLS*`
raised by a test that deliberately passes deprecated options to prove the TLS
floor still wins, which is the assertion working rather than a defect. It is
not reported.

The warning in sub-dimension 4 is a real defect and it is the platform-shaped
kind: it reproduces on Windows and CI is Linux, so the suite is green in both
places and only one of them prints it.

## CI/CD and quality gates — Grade: B+

| # | Sub-dimension | Status | Finding | Reproduction |
| --- | --- | --- | --- | --- |
| 1 | Three layers | PASS | Editor settings, pre-commit hooks, and CI on every pull request | The editor config, the hook config and the workflows |
| 2 | Gate coverage | PASS | Lint, format, types, tests, coverage, build, metadata, examples, SAST and secrets all run | The `test`, `build`, `security`, `secrets` and `examples` jobs, fanning into `gate` |
| 3 | Required checks | PASS | `gate` and `codeql` are required, and administrators are bound | The protection endpoint reports both contexts, `enforce_admins` true and an approving-review count of zero |
| 4 | Branch hygiene | PASS | Automatic head-branch deletion is on | The repository reports `delete_branch_on_merge: true` |
| 5 | Release ordering | FAIL | Nothing enforces that the release pull request merges first | Protection reports `strict: false`, so two green pull requests are mergeable in either order, and PLAYBOOK 5 records the consequence in its own words. Tracked as #217 |
| 6 | Audit step | PARTIAL | The 360 step was ungated, which is why four releases skipped it | `tests/test_release_audit_is_current.py`, added by the change carrying this report, closes it |

Every critical finding from August is closed here. The first report's headline
was that no check could stop anything because `main` was unprotected; two
contexts are now required, the administrator exemption is off, and the
single-maintainer trap — a review count nobody can satisfy — is avoided by
setting it to zero and relying on administrator enforcement instead.

Sub-dimension 5 is the finding this pass adds. `strict: false` is a deliberate
choice and a reasonable one for a repository this size, since requiring
branches to be up to date costs an update-plus-CI cycle per pull request. What
it leaves behind is that the changelog entry written on a release branch
describes the tree as of that commit, so anything merged between the merge and
the tag ships inside the release with nothing naming it. Both pull requests are
green either way and no signal distinguishes the orderings.

Sub-dimension 6 is the reason this audit exists, and it is the shape
`quality-gates-procedure-steps` describes: the steps either side of it are
gated and pass, so an operator running the sequence feels it checking the work
while the ungated step is simply not done.

All three of August's failures are closed, and two of them were critical. The
migration had moved the source without the settings around it; the settings
have since been reinstated and go beyond what the predecessor had, because
CodeQL is required rather than merely present.

Bandit reports no issues over 10848 lines and 30 suppressions, every one of
them a line-level `# nosec` naming a single check. That is the shape ADR-012
requires — nothing is skipped tree-wide from the configuration — so the count
is a record of reviewed decisions rather than of disabled analysis.

Sub-dimension 6 is a shape finding rather than a defect. The defaults are
correct today: verified peer certificate, hostname checking on, a declared
minimum version, and a floor applied after the caller's own options so it can
only be tightened. What #194 carries is that nothing about the interface makes
that hard to get wrong.

## Dependencies and viability — Grade: A

| # | Sub-dimension | Status | Finding | Reproduction |
| --- | --- | --- | --- | --- |
| 1 | Runtime dependencies | PASS | None | The dependency list in the packaging config is empty |
| 2 | Licensing | PASS | MIT, declared in SPDX form, with the file present | The packaging config and the LICENSE file |
| 3 | Toolchain lock | PASS | `uv.lock` is current and something refreshes it | The lock was last changed on 2026-08-21, and Dependabot is enrolled on the pip ecosystem weekly |
| 4 | Disaster recovery | PASS | Rebuildable from the repository alone | Certificates are generated rather than stored, and there is no external state |
| 5 | Lock-in | PASS | Standard library only, on Python 3.10 and newer | There is nothing to be abandoned by |

Unchanged from August, with one addition. The first report predated `uv.lock`;
the lock now exists, CI installs from it with the flag that refuses a stale
one, and Dependabot opens the refresh, so the three failure modes of a
committed lock — never installed from, never refreshed, resolved for one leg —
are each answered by something.

A library with no runtime dependencies cannot inherit a transitive
vulnerability, cannot break on someone else's release, and cannot be held
hostage by an unmaintained package. That is still worth more than any scanning
tool, and it is still a deliberate constraint recorded in the packaging config.
