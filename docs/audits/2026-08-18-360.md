# 360-Degree Audit — 2026-08-18

First audit of this repository, run at v0.1.0 before any decision to publish.
pyomb is a headless library, so this follows `360-headless`: the Value and
Discovery perspectives do not apply, and the Quality perspective is
re-projected into nine engineering dimensions, each reviewed under its own
restated lens.

Every finding below carries the command or file that demonstrates it. Nothing
here is marked UNVERIFIED, because findings that could not be demonstrated were
dropped rather than reported — two candidate findings died that way, both
described under Tests.

## Current bottleneck

**Security (C-)** — three findings, two of them blocking publication. This
repository was created to carry a clean history, and it currently has fewer
protections than the repository it replaced: secret scanning, push protection
and Dependabot are all disabled, because those are per-repository settings that
a new repository does not inherit. There is also no SAST anywhere, which the
project's own gate table makes a Layer 3 MUST.

None of this is a defect in the code. It is the migration having moved the
source without the settings around it.

## Protocol correctness — Grade: A-

| # | Sub-dimension | Status | Finding | Reproduction |
| --- | --- | --- | --- | --- |
| 1 | Wire assertions | PASS | 510 literal byte vectors across 26 of 41 test files | Counted by scanning the test sources for byte-string escapes |
| 2 | Checksum vectors | PASS | CRC values come from outside the library | `tests/test_rtu_crc.py` cites crccalc.com and the reference implementation in the Modbus over Serial Line specification |
| 3 | Type hierarchy | PARTIAL | 123 Liskov violations across the PDU hierarchy | Tracked as #6, frozen by error code rather than suppressed, so they stay counted |

The rule that matters most for a protocol library — assert against the
specification, never against your own output — is genuinely honoured. The CRC
vectors are the clearest case: they are external reference values, so a bug in
the checksum routine cannot make its own test pass.

The open Liskov finding is a real divergence between declared and actual
signatures, but it is recorded rather than hidden, and the frozen entries are
what stop it growing.

## Tests — Grade: B+

| # | Sub-dimension | Status | Finding | Reproduction |
| --- | --- | --- | --- | --- |
| 1 | Suite health | PASS | 370 tests and 87 subtests pass | A plain `pytest` run |
| 2 | Coverage | PASS | 84% overall, above the 80% floor CI enforces | A coverage run over the package |
| 3 | Weakest module | PARTIAL | `packets.py` at 79% is the only module below the floor and the largest absolute gap at 226 statements | The per-module coverage table; tracked as #1 |
| 4 | Known flake | PARTIAL | Server threads log to a closed capture stream at teardown | Tracked as #5; it reproduces on the pre-refactor baseline, so it is not a regression |

Two candidate findings were dropped here rather than reported, and the reason
is worth recording. A search suggested only one test file asserted against wire
bytes, which would have been a critical finding against this project's central
testing rule. Reading one of the supposedly bare files disproved it
immediately. A second attempt with a corrected pattern returned zero, also
wrong, because that search mode fails silently in this environment's locale.
The real number, counted with a script, is 510 vectors across 26 files.

The lesson is the one `360-output` warns about: a tool that runs cleanly and
returns a plausible number is the most convincing way to be wrong. Both false
readings pointed the same direction, and either would have produced a confident
finding that was the opposite of the truth.

## CI/CD and quality gates — Grade: C

| # | Sub-dimension | Status | Finding | Reproduction |
| --- | --- | --- | --- | --- |
| 1 | Three layers | PASS | Editor settings, ten pre-commit hooks, and CI on every pull request | The editor config, the hook config and the workflow |
| 2 | Gate coverage | PASS | Lint, format, types, tests, coverage, build, metadata and secrets all run | The test, build and secrets jobs |
| 3 | Required checks | **FAIL (critical)** | No check gates a merge, because `main` is unprotected | The branch protection endpoint returns 404 for `main`. Tracked as #12 |
| 4 | Branch hygiene | PARTIAL | Automatic head-branch deletion is off | Which is what forces a manual retarget when one pull request is stacked on another |

Every gate this project needs exists and passes. None of them can stop
anything. A red pull request merges as easily as a green one, and a direct push
to `main` bypasses the lot — which makes the pipeline a notification rather
than a gate, in the exact words of `quality-gates-layers`.

This is the cheapest finding in the audit to fix, and the one that makes every
other gate mean what it claims.

## Security — Grade: C-

| # | Sub-dimension | Status | Finding | Reproduction |
| --- | --- | --- | --- | --- |
| 1 | Secret scanning | **FAIL (critical)** | Secret scanning, push protection and Dependabot are all disabled | The repository's security-and-analysis settings report every feature disabled. Tracked as #10 |
| 2 | SAST | **FAIL (critical)** | No bandit and no CodeQL, against a Layer 3 MUST | No security tool appears in the packaging config or the hooks, and the CI workflow is the only one. Tracked as #11 |
| 3 | Supply chain | FAIL | All five action references use mutable tags rather than commit SHAs | The workflow pins checkout and setup-python by major version. Tracked as #13 |
| 4 | Credentials in history | PASS | Nothing to find, because the history is one commit | The secrets job passes over the full history |
| 5 | CI permissions | PASS | Scoped to the minimum | The workflow declares read-only contents access |
| 6 | Transport defaults | PASS | Verified peer certificate, hostname checking, and no custom cipher string | Relaxing any of them takes an explicit argument, as the README states |

The code's own security posture is good: secure-by-default TLS, least-privilege
CI, no runtime dependencies to inherit a vulnerability from, and a genuinely
clean history.

The failures are all in the repository around the code, and all three arrived
with the migration. The predecessor enabled secret scanning and push protection
in response to a real credential exposure; those settings are per-repository
and did not travel. This repository therefore has weaker protection than the
one it was created to improve on, and it is the one intended to go public.

| # | Sub-dimension | Status | Finding | Reproduction |

| 2 | Licensing | PASS | MIT, declared in SPDX form, with the file present | The packaging config and the LICENSE file |

hostage by an unmaintained package. That is worth more than any scanning tool,
and it is a deliberate constraint recorded in the packaging config.
