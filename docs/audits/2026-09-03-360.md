# 360-Degree Audit — 2026-09-03

Fourth audit of this repository, run on the release branch for v0.6.0. It is
owed because that is a minor release; ADR-033 narrowed the obligation to minor
and major releases so that running the audit is the cheaper option than writing
a document declining it.

The gate would have accepted the 2026-09-01 report. That report says on its
face that it was run on the release branch for v0.5.0, and 3.23 compares only
against the release before the one being cut, which v0.5.1 and v0.6.0 share a
date with. The comparison passes and says nothing about the sixteen commits
since, three of which break the public API. Running the audit was a decision
taken against the gate's floor rather than because the gate demanded it.

pyomb is a headless library, so this follows `360-headless` as all three
earlier reports did: the Value and Discovery perspectives do not apply, and the
Quality perspective is re-projected into nine engineering dimensions, each
reviewed under its own restated lens.

The template prefers one isolated subagent per dimension. This pass ran
sequentially with the lens restated before each dimension, which the template
permits when parallel agents are not available. That is a weaker isolation than
the template asks for and is recorded here rather than left for a reader to
infer, exactly as the previous pass recorded it.

Every finding below carries the command or file that demonstrates it. Nothing
is marked UNVERIFIED. One candidate finding was dropped after checking and is
recorded under the dimension it belongs to, because a dropped finding is the
part of an audit that is otherwise invisible.

Two findings were produced by this release rather than inherited, and one of
them was introduced by the change this same session shipped. Both are recorded
in the same shape as the rest.

The 2026-08-18, 2026-08-29 and 2026-09-01 reports are left exactly as written.
Their grades are observations of those dates rather than values to re-derive.

## Current bottleneck

**Dependencies and viability (B)**, and it is a new bottleneck rather than the
one the last three reports named.

Two Dependabot pull requests have been open since 2026-09-02 and neither can
merge. Each bumps one half of `github/codeql-action`, the action refuses to run
when its halves disagree, and the required check that fails is the one the
action itself produces. There is no ordering that resolves it. The pins the
supply-chain control rests on are therefore frozen until someone intervenes by
hand, and `dependabot.yml` states in its own comment that a pin nothing moves
is a pin that goes stale.

This displaced the previous headline rather than resolving it. Cognitive
complexity is still ungated, was a FAIL on 2026-08-18, 2026-08-29 and
2026-09-01, and is a FAIL here. #149 has been open throughout. A fourth
consecutive report is past the point where restating it adds information.

What the release did close is the other long-running pair. #192 renamed the
camelCase surface and #194 grouped the TLS settings, so API contract and
Security both lose the findings they carried into three reports. Security
reaches A for the first time.

The finding is narrow and stating it precisely matters. `relaxations()` answers

The dimension reaches A for the first time. Sub-dimension 6 was PARTIAL on all
three previous reports and is the finding #194 closed.

What changed is not that the defaults got stronger -- they were already
correct, and the previous report said so. What changed is that a weakening is
now answerable. The eight loose keyword arguments could be read only by reading

sentinel is a distinct type rather than `None`.

Bandit reports no issues, and every suppression is a line-level `# nosec`
naming a single check, which is the shape ADR-012 requires. Nothing is skipped
tree-wide from the configuration.

One candidate finding was dropped, and recording it saves the next pass the

repository settings, which looks like a gap on a project that mints private
keys locally. It is not one here: the `secrets` job runs the gitleaks binary
with no `.gitleaks.toml`, so it carries the default ruleset, which includes a
private-key rule, and it reads the full history rather than the tip. The
control that would catch a committed key already runs, in CI, on every pull
request.

## Dependencies and viability — Grade: B

| # | Sub-dimension | Status | Finding | Reproduction |
| --- | --- | --- | --- | --- |
| 1 | Runtime dependencies | PASS | None | `dependencies = []` in the packaging config |
| 2 | Licensing | PASS | MIT, declared in SPDX form, with the file present | The packaging config and the LICENSE file |
| 3 | Toolchain lock | PASS | `uv.lock` is current and CI installs from it with `--locked` | Last changed 2026-08-21; the pip ecosystem is enrolled weekly with `increase-if-necessary` |
| 4 | Update mechanism | FAIL | The actions bump path is deadlocked | #292 and #293 each bump one half of `github/codeql-action`, the action refuses a version mismatch, and the check it fails is required. Neither can merge in any order. Tracked as #295 |
| 5 | Disaster recovery | PASS | Rebuildable from the repository alone | Certificates are generated rather than stored, and there is no external state |
| 6 | Lock-in | PASS | Standard library only, on Python 3.10 and newer | There is nothing to be abandoned by |

The dimension drops from A, and sub-dimension 4 is a new row rather than a
re-grading of an old one. The previous report folded the update mechanism into
sub-dimension 3 and read its silence as health: "no open Dependabot pull
request and a lock eleven days old is the expected state rather than a stall."
That reading was correct for the pip ecosystem, where a floor moves only when a
release requires it. It does not transfer to the actions ecosystem, which keeps
the default strategy precisely so the SHA pins keep moving, and where silence
now means two pull requests that cannot merge rather than nothing to do.

Splitting the row is the change that makes the dimension able to see this at
all. A lock that is current and a bot that can land its work are different
claims, and the previous shape could report the first while the second was
failing.

The failure is structural rather than a bad release. `base-config` names the
pattern: an updater that splits interlocked packages into separate pull
requests produces a pair where each passes alone and the combination is what is
needed. Its two remedies are rebasing the second onto the merged first, or
grouping them. The first does not apply, because neither can be the merged
first. `.github/dependabot.yml` carries no `groups` entry for the
`github-actions` ecosystem, so the next CodeQL release deadlocks identically.

Sub-dimension 1 is unchanged and remains the strongest single fact here. A
library with no runtime dependencies cannot inherit a transitive vulnerability,
cannot break on someone else's release, and cannot be held hostage by an
unmaintained package. The new module changed nothing about that: `tls.py`
imports `ssl`, `enum` and `dataclasses`, all standard library.
