# 360-Degree Audit — 2026-09-09

Fifth audit of this repository, run ahead of v0.8.0. It is owed twice over:
that release is minor, and the 2026-09-08 record already said the next one
could not be a second consecutive decline — ADR-033 refuses that shape, and
2026-09-08 was itself a decline. Nothing here re-derives that record's
argument; it is the reason this pass exists rather than another one.

pyomb is a headless library, so this follows `360-headless` as all four
earlier reports did: the Value and Discovery perspectives do not apply, and
the Quality perspective is re-projected into the same nine engineering
dimensions the project has used since the first report — Architecture, API
contract, Protocol correctness, Code quality, Tests, CI/CD and quality gates,
Security, Documentation, Dependencies and viability.

Unlike the four earlier passes, this one ran the template's preferred shape:
nine isolated subagents in parallel, one per dimension, each with a clean
context and its own restated lens, rather than one reviewer switching roles
in sequence. That is stronger isolation than any previous report recorded.

Every subagent was given the 2026-09-03 report — the last real audit, run on
the v0.6.0 branch — and told to reconcile against it rather than re-derive
from zero. Two corrections surfaced in the parent's own briefing during that
reconciliation, worth recording because they could otherwise read as
findings: `defines.py` and `errors.py` were named as part of the deprecated
module set moved by epic #413. They are not — ADR-054 explicitly considered
and rejected moving them, and both remain full, unshimmed modules by design.
Separately, the briefing called the pip Dependabot ecosystem "deliberately
not enrolled"; it is enrolled weekly, unchanged since v0.6.0, and the
2026-09-03 report already recorded that correctly. Neither correction changed
a grade; both are recorded here rather than left for a reader to notice on
their own.

The seven findings the 2026-09-03 report tracked as open issues — #149,
#170, #210, #217, #262, #295, #296 — are confirmed closed on the tree, not
merely on the tracker, by the dimension that owns each one. Every one of them
is a genuine fix, not a relabeled won't-fix.

## Issues created

#426, on six blind `except Exception` catches carried into `transport/` and
`simulators/` by the move. #427, on a leftover disabled line in both demo
programs. #428, on the mutual-TLS integration tests silently skipping since
the move — the finding behind this report's bottleneck. #429, on the
release-ordering check having no record that it was actually run before a
tag.

## Current bottleneck

**Tests (B+)**, and it is a new bottleneck rather than the one the last real
report named.

The `pdu`/`adu`/`transport`/`simulators` move (epic #413) reorganized the
test tree to mirror it, and in doing so broke the certificate-path
arithmetic in the mutual-TLS integration tests. They have not failed since —
they have not run at all, on either supported Python version, and nothing in
the pipeline was positioned to notice a skip where a pass was expected.
Tracked as #428.

This displaces the previous headline. Code quality's two long-running
findings — #149 (complexity ungated) and #170 (the ruff and mypy freezes) —
are both closed and verified live: every gate runs clean with zero
exemptions beyond the two documented test/checks docstring waivers. That
bottleneck, which capped four consecutive reports, is gone.
