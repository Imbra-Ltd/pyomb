# 360-Degree Audit — 2026-09-08 — skipped

The 360-degree audit is declined for **v0.7.0**. This document is the record of
that decision, which is what PLAYBOOK 4.4 asks for and what
`checks/test_release_audit_is_current.py` reads.

The decline was the owner's call, taken with the gate's state on the table: the
2026-09-03 report postdates v0.6.0, so nothing blocked the release either way.

## Reason

The 2026-09-03 report is five days old. It graded the repository B overall
across nine dimensions with seven findings and none critical, and it was run on
the release branch for v0.6.0 — the release immediately before this one.

That is the whole of the case, and it is weaker than the case the 2026-08-31
record made. This record does not repeat that record's argument.

## What is different from the 2026-08-31 decline

That record rested on the tree not having moved: no source module changed
between the audited commit and the release, and the check behind that sentence
printed nothing. Neither holds here. Every module in `src/` changed between
v0.6.0 and this release:

```
git diff --stat v0.6.0..HEAD -- src/

 src/pyomb/client_simulator.py            |  303 ++--
 src/pyomb/defines.py                     |    9 +-
 src/pyomb/errors.py                      |  289 ++--
 src/pyomb/logger.py                      |   43 +-
 src/pyomb/packets/__init__.py            |  109 ++
 src/pyomb/packets/base.py                |  224 +++
 src/pyomb/packets/framing.py             | 1001 +++++++++++++
 src/pyomb/{packets.py => packets/pdu.py} | 2242 ++++++++-----------------
 src/pyomb/server_simulator.py            |  453 +++---
 src/pyomb/stream.py                      |  277 ++--
 src/pyomb/tls.py                         |   68 +-
 12 files changed, 2751 insertions(+), 2423 deletions(-)
```

Seventy-one commits are carried. Among them a package split, a new framing
module, a change to how the server routes a request, a change to what it does
with a PDU it cannot parse, and the removal of two deprecated aliases. Three of
the nine dimensions the audit scores — architecture, API contract and protocol
correctness — read a surface that this release rewrote.

So the reason above is a judgement about cost and timing, not a demonstration
that there is nothing new to read. Stating that is the point of the record.

## What this does not claim

Declining the audit is not a finding that the repository is clean. The seven
findings the 2026-09-03 report raised stand as written, and the ten open issues
— three at P2, seven at P3 — are still open. A skip record says the step was
weighed and passed over, not that its subject was inspected.

The 2026-09-03 grades are observations of that date. They are not re-derived
here, and nothing in this document revises them. In particular, the bottleneck
that report named is not re-assessed, and neither is the grade it rests on.

## What it costs

ADR-033 narrowed the audit obligation to minor and major releases on the
reasoning that running it would then be cheaper than writing a document
declining it. This record is the case where that reasoning did not hold, which
is worth seeing rather than leaving implicit.

The specific cost is that v0.7.0 ships the largest source delta of any release
since the audits began, and no pass has read it. Whatever the next report finds
in that surface will have been shipped for however long the interval turns out
to be.

## When the next one is owed

At the next minor or major release. The gate compares the newest report against
the release preceding the version the package reports, so the 2026-09-03 report
will not clear it — a report has to postdate v0.7.0. A patch release owes
nothing, neither a report nor a record.

This is the first decline since the cadence changed, so nothing is inherited
here and nothing compounds. A second consecutive decline would put two releases
and this delta on one report, and that is the shape the gate exists to refuse.
