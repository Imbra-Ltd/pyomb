# 360-Degree Audit — 2026-08-31 — skipped

The 360-degree audit is declined for **v0.4.2**. This document is the record
of that decision, which is what PLAYBOOK 4.4 asks for and what
`tests/test_release_audit_is_current.py` reads. Four releases were cut with
the step passed over in silence; declining it in writing is the option that
gate leaves open.

## Reason

The 2026-08-29 report is two days old. It graded the repository B+ overall
across nine dimensions with zero critical findings, and it was itself the pass
that closed the four-release gap. Re-running the nine dimensions two days later
would re-derive the same grades against substantially the same tree.

The five commits between v0.4.1 and this release are documentation and a test
policy change. None of them touches a dimension the audit scores:

| Commit | What it changes |
| --- | --- |
| `84ae6b7` | Moves four vendor PDFs and a tutorial into `docs/specs/` |
| `09f6bdb` | A dev journal entry |
| `42373d8` | Stops holding Markdown to printable ASCII, in one test |
| `1fffd39` | Adds `docs/design/` and one direction note the project has not adopted |
| `de7c090` | A dev journal entry |

No source module changed. The check behind that sentence compares the tag
against the commit this release branch was cut from, `de7c090`, rather than
against the branch tip: `git diff --stat v0.4.1..de7c090 -- src/` reports
nothing. Against the tip it would report the version literal in
`src/pyomb/__init__.py`, which the release itself edits and which is the one
source edit v0.4.2 carries.

## What this does not claim

Declining the audit is not a finding that the repository is clean. The ten
findings the 2026-08-29 report raised stand as written, and the three tracked
ones — #196 on range-checking bounded fields, #149 on the unbound
cognitive-complexity gate, and #217 on the unenforced release ordering — are
still open. A skip record says the step was weighed and passed over, not that
its subject was inspected.

The 2026-08-29 grades are observations of that date. They are not re-derived
here, and nothing in this document revises them.

## When the next one is owed

At the release after this one. The gate compares the newest report against the
release preceding the version the package reports, so v0.4.3 or v0.5.0 will
fail until a report postdates v0.4.2. Two consecutive skips would mean three
releases resting on the 2026-08-29 pass, which is the shape this gate exists to
refuse — so the next release runs the audit rather than declining again.

## Addendum — 2026-08-31

This record now also covers **v0.4.3**, cut the same day as v0.4.2.

**What changed.** Two things, both after the section above was written. The
owner scheduled the next 360-degree audit for the point at which the open
backlog reaches zero, rather than for the next release. Separately, the gate's
comparison was loosened to accept a record dated the same day as the previous
release, so this document clears it for v0.4.3 without being reissued.

**What this supersedes.** The final sentence of "When the next one is owed" —
that the next release runs the audit rather than declining again. It does not.
The audit is deferred to the zero-backlog point, and v0.4.3 is the second
consecutive release resting on the 2026-08-29 pass.

**What it costs.** Exactly what that sentence warned of. Three releases now
rest on one report, and the deferral is open-ended rather than dated: the
backlog stands at 27 open issues, so the trigger is a condition rather than a
date. Nothing watches it. The next release inherits this addendum and not a
fresh decision, which is the failure mode a skip record exists to make visible
rather than to prevent.

**What is left as written.** Everything above this addendum. The reason, the
commit table, and the statement that declining is not a finding of cleanliness
are observations of the day they were made, and are not revised here. The ten
findings of the 2026-08-29 report still stand, and the three tracked ones are
still open.
